# Third-Party-Brain

**🌐 Language: 한국어 (이 문서) · [English](./README.en.md)** · 💬 [Discussions (피드백·질문)](https://github.com/11pyo/Third-Party-Brain/discussions)

> **거의 모든 생각과 수행을 AI에게 맡기는 "뇌 + 손발"을 만드는 프로젝트.**
> 지금은 그 첫 조각 — **파일 몇 개로 바로 도는** AI 검색 지식 아카이브("제3의 뇌") + 직접 복제하는 방법론(블루프린트).

> 🧭 **두 레포 (별개 도구, 둘 다 바로 돎):** 🧠 **Third-Party-Brain** = 지식 뇌(검색·복제) · 🗂️ **[AI 협업 대시보드](https://github.com/11pyo/ai-collab-dashboard)** = 동시기록 안전 작업 보드. *처음이면 브레인부터.*

> 🌍 **도메인 무관 — SAP 전용 아님.** 본보기 사례가 SAP SD 운영이라 예시에 SAP 용어(T-Code 등)가 나올 뿐, **패턴 자체는 어떤 팀·모듈·회사·주제에도 그대로** 적용됩니다 — IT 런북, 인사 절차, 고객지원 FAQ, 연구 노트, 사내 위키 등. *당신의 도메인 용어로 채우면 됩니다.*

하나의 HTML 파일(데이터+화면+검색) + 파이썬 도구 몇 개 + 로컬 AI 검색으로 구성됩니다. 외부 DB·서버 설치 없음, 오프라인 가능.

## 🤖 AI로 바로 빌드·실행 · Build / run with an AI
**✅ 데모 포함** — 클론하면 가짜 샘플 아카이브가 **바로 돕니다**. 폴더를 AI에게 주고 **"`AGENTS.md` 읽고 셋업해줘"** 라고 하면, AI가 **쉬운 선택**을 제시합니다:
- **Ⓐ 데모 보기** → `reference-implementation/archive/`(`pip install -r requirements.txt` → `python archive-server.py`) · `reference-implementation/dashboard/`(브라우저로 열기, 빌드 불요).
- **Ⓑ 내 아카이브 만들기** → AI가 **먼저 당신에게 묻습니다(STEP 0)**: 주제(도메인)·카테고리·**민감정보 금지목록**·코드 표기·동의어 + **실제 채울 지식 내용**(지어내지 않음). 절차 = `archive-blueprint/04-replication-playbook`.

**준비물:** Python 3.8+ (아카이브 검색서버). ※ *AI 자연어 답변* 기능만 로컬 `claude` CLI 필요 — 검색·인테이크·대시보드는 CLI 없이도 동작.

## 💡 이럴 때 특히 유용합니다 (활용 시나리오)

### 🚨 담당자가 급하게 퇴사할 때 — 인수인계 공백 메우기
운영 지식이 **한 사람 머릿속·흩어진 메신저·메일**에만 있으면, 그 사람이 갑자기 떠나는 순간 업무가 멈춥니다(이른바 *버스 팩터 1*).
이 아카이브 패턴은 그 위험을 구조적으로 없앱니다.

- **떠나기 전**: 전임자가 알고 있는 T-Code·절차·트러블슈팅·담당자 연락 체계를 아티클로 쌓아두면, **하나의 검색 가능한 HTML**로 남습니다.
- **떠난 후**: 후임자는 *"월초에 뭐 해요?"* 처럼 **자연어로 물어보면** 로컬 AI가 아카이브를 근거로 답하고, 원문 위치까지 바로 안내합니다. 두꺼운 매뉴얼을 처음부터 읽지 않아도 됩니다.
- **검증**: 떠나기 직전, 전임자에게 **링크 하나만 공유**(같은 네트워크)하면 후임이 만든 아카이브를 빠르게 감수받을 수 있습니다.

> 실제로 이 블루프린트는 **SAP SD 운영 담당 인수인계** 과정에서, 선임의 지식을 빠르게 구조화하고 검증받기 위해 만들어졌습니다.

### 그 밖의 활용
- **신규 입사자 온보딩** — "이건 어떻게 처리해요?"를 사람 대신 아카이브가 답함. 선임의 반복 질문 부담↓.
- **1인 의존 업무의 분산** — 속지식(tacit knowledge)을 검색 가능한 자산으로 전환.
- **산발 지식의 단일화** — 메신저·메일·개인 메모에 흩어진 노하우를 한 곳에.
- **감사·규정 대응** — 처리 절차와 근거를 날짜·이력과 함께 보존.
- **부서/모듈 확장** — 한 번 만든 패턴을 MM·FI·HR 등 다른 영역에 그대로 복제.

## 이 저장소에 들어있는 것

이 저장소는 **방법론 문서(블루프린트)** + **실행 가능한 익명 레퍼런스 구현**으로 구성됩니다.
**주 콘텐츠는 「지식 아카이브 + AI 협업」**입니다. `archive-blueprint/`의 설계·알고리즘·플레이북을 따라 직접 재현해도 되고, `reference-implementation/`의 동작본을 바로 돌려봐도 됩니다 — 데이터는 전부 가상 샘플입니다.
- **아카이브 엔진** (`reference-implementation/archive/`): BM25 검색서버 · 인테이크 · TUI + 샘플 `archive.html`.
- **AI 협업 대시보드** (`reference-implementation/dashboard/`): 동시기록 안전(추가전용 + id-병합) 칸반·문의보드. ※ **별도 전용 레포로도 존재** → https://github.com/11pyo/ai-collab-dashboard

```
Third-Party-Brain/
├─ README.md / README.en.md  ← 시작점 (KO / EN) · entry point
├─ AGENTS.md / CLAUDE.md      ← ⭐ AI 자동 온보딩 (기능·룰·방향) · agent auto-onboarding
├─ archive-blueprint/
│  ├─ 00-INDEX.*            진입점 · 아티팩트 맵 · 불변식(INV) · ⛔동기화 지침
│  ├─ 01-overview-architecture.*   개요 · 아키텍처 · 기술스택
│  ├─ 02-buildup-process.*         빌드업 프로세스(구축 이력) · 흔한 함정
│  ├─ 03-algorithms-scaling.*  ⭐  검색·인테이크 알고리즘 + 규모별 확장 임계점
│  ├─ 04-replication-playbook.*    새 아카이브 만들기 단계별 절차
│  ├─ 05-operational-layer.*       운영 레이어 — 무서버 대시보드·충돌없는 로그·조직맵
│  ├─ 06-automation-and-ops-model.*  자동화·읽기전용 운영 안전모델·공개수준 계층
│  ├─ 07-dashboard-operating-guide.*  대시보드 운영 규칙 & 사용법(문의로그 CLI·추가전용 id-병합)
│  └─ CHANGELOG.*                  프로그램·구조 변경 이력
└─ reference-implementation/    ⭐ 실행 가능한 익명 동작본 (가상 샘플)
   ├─ archive/                ⭐ 제3의뇌 아카이브 엔진 — BM25 검색서버·인테이크·TUI + 샘플 archive.html
   └─ dashboard/              AI 협업 대시보드 (07 챕터) — 별도 전용 레포: 11pyo/ai-collab-dashboard
```

### 문서는 2벌씩 (AI용 + 사람용)
- **`*.ai.md`** — 다른 대화 세션의 **AI 에이전트가 읽는 용도**. 압축적·지시형·구조화(메타데이터 포함).
- **`*.human.md`** — **사람이 읽는 용도**. 배경과 이유를 서술.

> 같은 내용을 다른 방식으로 표현한 쌍입니다. 클론한 뒤 AI에게 작업을 시키려면 `.ai.md`를, 직접 이해하려면 `.human.md`를 보세요.

## 빠른 시작 — 클론 후 똑같이 만들기

```bash
git clone <이 저장소 URL>
cd Third-Party-Brain
```

1. **읽기** — `archive-blueprint/00-INDEX.human.md`(사람) 또는 `00-INDEX.ai.md`(AI)부터 번호 순서대로.
2. **이해** — `01`(아키텍처) → `03`(검색/인테이크 알고리즘)으로 구조와 핵심 로직 파악.
3. **복제** — `04-replication-playbook.*`의 6단계를 따라 본인 도메인 아카이브를 생성:
   - 0단계: 도메인 파라미터 수집(카테고리·동의어·민감정보 목록·코드 표기법)
   - 1단계: 빈 골격 HTML(인라인 CSS 컴포넌트 + 사이드바)
   - 2단계: 아티클 작성 규격 `<article id data-tags>`
   - 3단계: 경량 인덱스(`*-structure.md`) 작성
   - 4단계: 파이썬 도구 3종(검색서버·인테이크·메뉴) 작성 + 도메인 파라미터화
   - 5단계: 검증(검색·인테이크·서버·LAN ≥3 케이스)
   - 6단계: 운영 규율 인계
4. **AI에게 맡기려면** — 클론 폴더에서 AI에게 "이 `archive-blueprint` 보고 ○○ 아카이브 만들어줘"라고 하면, `04-*.ai.md`의 트리거에 따라 절차대로 진행합니다.

> ⚙️ **블루프린트(방법론) + 실행 레퍼런스 구현 둘 다 공개**. `01`·`03`·`04`의 .ai.md에 검색 파이프라인·동의어맵·인테이크 판정·불변식이 **코드 수준으로 기술**돼 있고, `reference-implementation/`에 **아카이브 엔진과 대시보드의 실행 가능한 익명 동작본**(가상 샘플)을 함께 제공합니다. 새 AI 세션은 루트 [`AGENTS.md`](./AGENTS.md)부터 읽으면 기능·룰·방향이 바로 온보딩됩니다.

## 핵심 설계 원칙 (요약)

1. **이식성** — 데이터는 단일 HTML. 외부 DB 없음. 복사만 하면 어디서든 열림(오프라인 가능).
2. **단순함** — 파이썬 표준 라이브러리만. `python x.py` 한 줄로 실행(비개발자 친화).
3. **검색 친화** — 모든 아티클에 검색 키워드(`data-tags`) 부여. 사람·AI 모두 탐색 용이.
4. **안전** — 비밀번호·IP·계정·인증서 등 **민감정보는 절대 저장하지 않음**.
5. **로컬 AI 결합** — 로컬 LLM CLI로 자연어 검색. 별도 API 키·비용 없이, 데이터 외부 유출 없이 동작.

자세한 불변식(INV1~INV9)과 규모별 확장 임계점(N≤200 / 500 / 1000)은 `00-INDEX` · `03-algorithms-scaling`을 참고하세요.
