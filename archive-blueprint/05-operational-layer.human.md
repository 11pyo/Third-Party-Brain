# 운영 레이어 — 대시보드 · 충돌없는 로그 · 조직맵 (사람용)

정적 아카이브(`archive.html`) 위에 얹는 **"일하는 레이어"**입니다. 아카이브가 *지식*이라면, 이 레이어는 *진행 중인 일과 사람*을 다룹니다.
원본 사례에서 이 레이어가 가장 크게 자라났고, 정적 아카이브보다 재사용 가치도 큽니다. 핵심은 셋입니다.

## 1. 업무 대시보드 (서버 없이 도는 칸반)

- 단일 HTML(`task-board.html`) + 데이터 파일. **더블클릭으로 브라우저에서 열림**(별도 서버 불필요).
- 보드 3종: **일회성 태스크**(접수→진행중→대기→완료) · **정기업무**(주/월/연) · **문의 처리이력**.
- 카드 = ID + 제목 + 요청자 + 기한 + 다음 액션 + 상세(접기/펼치기). 완료 컬럼은 **높이 고정·스크롤**, 카드는 **최신순**.
- **정본은 사람이 읽는 마크다운**(`tasks.md`), 화면은 그걸 미러링한 HTML. 정본↔화면 동기화가 규율.

## 2. ⭐ 충돌 없는 추가전용 로그 (여러 세션이 동시에 써도 안전)

이 레이어의 핵심 패턴입니다. 여러 AI 세션(또는 사람+AI)이 같은 로그를 동시에 갱신해도 충돌이 안 나게:

- **추가만 한다 (append-only)** — 한 줄 = 한 이벤트. 기존 줄을 고치지 않고 새 줄을 *덧붙임*.
- **id로 병합한다 (id-merge)** — 같은 id로 나중에 덧붙인 줄이 앞 줄을 *덮어쓰며 병합*. → 상태 전이(접수→진행중→완료)가 "수정"이 아니라 "덧붙임"으로 표현됨.
- **헬퍼로만 쓴다** — 로그 파일을 직접 편집하지 않고, 작은 스크립트(`log-*.py`)가 줄을 덧붙임. 두 세션이 동시에 덧붙여도 줄이 섞이지 않음(파일 append는 사실상 원자적).
- **file:// 우회** — 브라우저가 로컬 파일을 fetch 못 하는 제약을, 로그를 `<script src>`로 불러오는 방식으로 우회(데이터를 JS push-log로 둠).

> 왜 중요한가: **"여러 자율 AI가 같은 작업판을 드리프트 없이 동시 갱신"**이 잠금·DB 없이 가능해집니다.

## 3. 조직·이해관계자 맵 (AI가 유지보수)

- 나와 엮이는 조직/담당/채널을 한 표로. 문의가 오면 "누가·어디·뭘 주로"를 즉시 식별·라우팅.
- ⭐ **자동 갱신 규율**: 업무를 처리할 때마다 점검 — ①새 조직 등장 → 행 추가 ②기존 조직 새 유형 → 보강 ③담당·채널 변경 → 반영. 이 규율을 **프로젝트 지침**(예: 에이전트 규칙 파일)에 박아 어느 세션이 와도 같게 유지.
- 보안: 조직·역할·이름(직급)·채널만. **사번·전화·이메일은 비공유 로컬에.**

## 설계 원칙

1. **정적 우선** — 대시보드도 서버 없이(파일 더블클릭). 공유는 아카이브 검색서버 `--share`에 얹거나 파일 복사.
2. **동시성은 append-only로** — 락 대신 "덧붙이고 병합". 손실·충돌 0.
3. **AI가 유지보수하는 살아있는 문서** — 사람이 매번 갱신하는 게 아니라, 업무 흐름에 *규율로* 묶어 AI가 갱신.
