# 새 아카이브 만들기 — 단계별 안내 (사람용)

다른 부서나 다른 주제로 똑같은 아카이브를 만들고 싶을 때 따라 하는 순서입니다.
AI에게 "이 청사진(`archive-blueprint`) 보고 ○○ 아카이브 만들어줘"라고 하면 이 순서대로 진행합니다.

## 0단계 — 먼저 정할 것

새 아카이브를 시작하기 전에 이것들을 정합니다:

- **주제** — 무엇에 대한 아카이브인가? (예: 구매 모듈 운영, 인사팀 절차)
- **카테고리** — 글을 어떻게 나눌 건가? (기존 5종을 그대로 써도 되고, 주제에 맞게 바꿔도 됨)
- **민감정보 목록** — 저장하면 안 되는 것 (비밀번호·IP·계정 등)
- **코드 표기법** — SAP라면 "코드 — 화면명" 형식 유지
- **비슷한 말 사전** — 사람들이 쓰는 말과 자료 속 용어가 다를 때 연결해줄 목록

## 1단계 — 빈 골격 만들기

기존 `archive.html`의 디자인(CSS) 부분을 그대로 복사해서 빈 껍데기를 만듭니다.
사이드바 메뉴 틀과 카테고리만 잡아두고, 글은 아직 비어 있는 상태로 둡니다.

## 2단계 — 글 채우기

각 글은 정해진 양식으로 작성합니다:
- 고유 ID (한번 정하면 바꾸지 않음)
- 검색 키워드 (`data-tags`) — **여기에 비슷한 말을 풍부하게 넣을수록 검색이 잘 됩니다**
- 제목, 카테고리 배지, 날짜
- 본문 (섹션별로 나눠서)

## 3단계 — 목차 파일 만들기

`구조.md` 같은 목차 파일을 만들어 글 목록·개수·키워드를 정리합니다.
이게 있어야 AI가 매번 거대한 본체를 다 안 읽고도 구조를 파악합니다.

## 4단계 — 도구 3개 복사 + 손보기

`archive-intake.py`, `archive-menu.py`, `archive-server.py` 세 개를 복사한 뒤,
**주제에 맞게 바꿀 부분만** 수정합니다:
- 파일 경로/이름
- 비슷한 말 사전
- 카테고리 분류 기준
- 충돌 패턴
- 포트 번호 (기존 것과 겹치지 않게)

> 한글 깨짐 처리, Claude 찾기, 공유 기능, 서버 뼈대는 **주제와 무관하므로 그대로 둡니다.**

## 5단계 — 반드시 테스트

- **검색**: 대표 질문 3개를 넣어 관련 글이 잘 나오는지
- **입력 도우미**: 중복·신규·충돌 각 1개씩 넣어 판정이 맞는지
- **서버**: 브라우저에서 열리고, AI 답변이 한글로 안 깨지고 나오는지
- **공유**: 공유 모드로 켜서 다른 PC에서 접속되는지

## 6단계 — 운영 규칙 넘기기

다음 담당자에게 이 규칙을 전달합니다:
- 글 고치면 세 곳(메뉴·개수·목차) 같이 고치기
- 새 정보는 입력 도우미로 먼저 검사
- 민감정보 저장 금지
- 글이 많아지면 `03-algorithms-scaling` 문서의 분기점을 보고 검색 방식 바꾸기
