# 보조 노트 — 이 아카이브 패턴 vs 범용 LLM‑위키 도구

> **무엇**: 이 저장소의 "검색 가능한 단일 HTML 운영 아카이브" 패턴을, 요즘 흔한 **범용 LLM‑위키 도구**
> (예: Karpathy식 *LLM Wiki*, 일부 에이전트 프레임워크의 `wiki` 스킬 — 세션을 넘어 누적되는 마크다운 지식베이스)와
> 비교하고, **둘을 결합하는 2단(scratch→canonical) 모델**을 정리한다.
> 본 노트는 번호 챕터(00~07)의 정본 방법론이 아니라 **포지셔닝 보조 문서**다 (.ai/.human 페어 없음).

---

## 1. 같은 뿌리 (공통 DNA)

둘 다 **"AI가 읽고 쓰며 세션을 넘어 누적되는 마크다운/구조화 지식베이스"** 라는 같은 발상에서 출발한다.

| 공통 개념 | 범용 LLM‑위키 | 이 아카이브 패턴 |
|---|---|---|
| 누적되는 지식 본체 | 다수의 `*.md` 페이지 | 단일 `archive.html`(다수 아티클) |
| 자동 유지 색인 | `index.md` | `archive-structure.md` |
| 카테고리 분류 | architecture / decision / pattern / debugging … | 도메인별 카테고리(예시: 용어·프로세스·설정·트러블슈팅·운영참조) |
| 상호 링크 | `[[page-name]]` | 사이드바 nav + `#앵커` |
| **벡터 임베딩 없이 키워드 검색** | keyword + tag 매칭 | `archive-server.py`의 BM25(char‑2gram) |
| 인테이크/적재 워크플로 | ingest/add | `archive-intake.py`(중복·충돌·배치 판정) |
| 건강성 점검 | lint(orphan·stale·broken‑ref) | 블루프린트 동기화 규율 + `archive-structure.md` 정합 |

> 즉, 검색·적재·색인·교차링크·"임베딩 없이 키워드로"까지 **설계 철학이 사실상 동일**하다.
> 이 패턴은 그 발상을 **손으로, 도메인·사람·거버넌스까지 확장해 구현한 풀버전**에 가깝다.

## 2. 갈라지는 지점

| 축 | 범용 LLM‑위키 | 이 아카이브 패턴 |
|---|---|---|
| **저장 형태** | 작은 `.md` 다수 | **단일 HTML**(렌더링되는 UI 내장) |
| **독자** | 대개 AI 전용·프로젝트 로컬·git‑ignore | **사람도 본다** — 브라우저 UI, LAN 공유(`--share`), 공개 가능 |
| **도구** | 프레임워크 내장 명령 | **자체 도구 스택**(인테이크·TUI·검색 서버) |
| **거버넌스** | lint 1종 | **`.ai.md`/`.human.md` 블루프린트 쌍 + CHANGELOG 의무 동기화**(INV8) |
| **범위** | 범용 개발 부스러기 지식 | **도메인 정본**(절차·코드·트러블슈팅) |
| **적재 시점** | 세션 종료 시 자동 캡처가 흔함 | **의도적 큐레이션**(인테이크 게이트 통과분만) |
| **민감정보** | 도구별 상이 | **금지(INV4)** — 비밀번호·IP·계정·실데이터 미저장 |

## 3. 언제 무엇을 쓰나

- **범용 LLM‑위키가 맞는 경우**: 빠르게 늘었다 줄었다 하는 **개발 스크래치**, 단일 프로젝트 한정, 사람이 거의 안 보고 AI만 참조, 거버넌스·공개 부담이 없을 때.
- **이 아카이브 패턴이 맞는 경우**: **사람+AI가 같이 보는 도메인 정본**, 인수인계·온보딩·감사 대응, LAN/공개 공유, "무엇이 정설인가"에 규율(충돌검사·동기화·민감정보 차단)이 필요할 때.

## 4. 결합 — 2단(scratch → canonical) 모델

둘은 경쟁이 아니라 **층**으로 합쳐진다. 핵심 통찰: **정본 아카이브는 "비싼" 저장소**다
(추가마다 3곳 동기화[INV3] + 인테이크 게이트[INV5] + 민감정보 차단[INV4]). 그래서 빠르게 튀어나오는
세션 단서를 담기엔 부적합하다. **위키 층을 "값싼 스크래치"로 두고, 검증된 것만 정본으로 승격**한다.

```
 세션 중 발견      범용 위키 add/ingest        [Tier 0 · 휘발성 · 무규율 · (보통)git-ignore]
                        │
            ╴╴ 검증·반복확인으로 "정본 가치" 확정 ╴╴
                        ▼
 검증된 지식      archive-intake.py  ◀── 승격 게이트(판정만: NEW / UPDATE / CONFLICT / REVIEW)
                        │
                        ▼
      verdict대로 archive.html 편집 + structure.md 동기화   [Tier 1 · 정본 · 공유 · 사람+AI]
                        │
                        ▼
      위키 카드 회수(delete)  ◀── 승격 완료분 제거(정본과 중복 방지)
```

**승격 게이트 매핑** (인테이크 판정 → 행동):

| 판정 | 의미 | 행동 |
|---|---|---|
| **NEW** | 아카이브에 없음 | 신규 아티클 작성(추천 카테고리 제시) + nav·카운트·`structure.md` 3곳 동기화(INV3) |
| **UPDATE** | 1개 아티클과 강관련 | 그 아티클에 섹션 추가/갱신 |
| **CONFLICT** | 절차 역전 등 모순 | ⛔ 자동승격 금지 → 사람이 확인 후 통합 |
| **REVIEW** | 연관 다수 | 사람 판단으로 배치 |

**카테고리 브리지(예)**: `architecture·environment → 설정` · `debugging → 트러블슈팅` ·
`pattern → 용어/프로세스` · `decision → 프로세스/운영참조` · `session-log → 대개 폐기(핵심만 추출)`.

## 5. 가드레일

- **무엇을 승격하나**: 재사용될 도메인 사실(절차·코드 동작·해법·용어 정의). **잔류/폐기**: 1회성 디버깅 경로·세션 한정 결정·미검증 가설.
- **민감정보(INV4)**: 위키 층에도 쓰지 않는다(설령 git‑ignore라도 원칙 유지). 실데이터·자격증명은 아카이브 **밖** 작업 영역에.
- **승격은 의도적 큐레이션**: CONFLICT/REVIEW는 반드시 사람 게이트. 일괄 자동 승격 금지.

## 6. 한 줄 결론

> 범용 LLM‑위키 = **"값싼 스크래치"**, 이 아카이브 패턴 = **"비싼 정본"**.
> 새 도구를 더 칠 필요 없이 — **위키엔 싸게 쌓고, `archive-intake.py` 게이트를 통과한 것만 정본으로 올린다.**
> 단일 세션이 프로젝트를 완주하고 에이전트가 인라인으로 큐레이션하는 운영에서는, 위키 층은 *선택*이며 정본 아카이브 + 인테이크 게이트만으로도 충분히 굴러간다.
