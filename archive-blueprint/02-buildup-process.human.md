# 빌드업 프로세스 — 어떻게 만들어졌나 (사람용)

이 아카이브는 한 번에 만든 게 아니라, 필요할 때마다 한 겹씩 쌓아 올린 결과물입니다.
나중에 비슷한 걸 또 만들 때 **"어떤 순서로 가면 되는지"** 참고용으로 정리합니다.

## 단계별 진화

| 단계 | 한 일 | 왜 |
|------|-------|-----|
| 1. 자료 모으기 | 인수인계 문서·구두 설명에서 용어·T-Code·업무절차를 뽑아 첫 글 작성 | 데이터가 있어야 시작 |
| 2. HTML로 통일 | 모든 글을 같은 양식(고유 ID + 검색 키워드)으로 맞추고 디자인 정립 | 일관성·검색 가능성 |
| 3. 목차 분리 | 글이 많아지자 `archive-structure.md` 목차를 따로 만듦 | 매번 거대한 파일 전체를 읽는 낭비 방지 |
| 4. 검증·정제 | 웹 검색·일반 지식과 비교해 충돌·중복·빠진 내용 점검 | 정확성 확보 |
| 5. 입력 도우미 | 새 정보를 넣기 전 중복·충돌을 자동 검사하는 도구 제작 | 아카이브가 꼬이지 않게 |
| 6. 메뉴 화면 | 검색·입력·현황을 메뉴로 탐색하는 대화형 도구 | 사용 편의 |
| 7. AI 검색 | 브라우저에서 질문하면 Claude가 답하는 서버 추가 | 자연어로 찾기 |
| 8. 검색 품질 개선 | "월간"으로 물어도 "월말 결산"을 찾도록 비슷한 말 확장 | 검색 누락 해결 |
| 9. 자동 이동 | 답변하면 해당 글로 화면이 자동 스크롤되고 강조 | "어디 있는지" 바로 보이게 |
| 10. 공유 기능 | 같은 네트워크 동료가 접속하도록 공유 모드 추가 | 검증·협업 |

## 만들면서 반복해서 부딪힌 문제들

나중에 같은 함정에 빠지지 않도록 기록합니다:

1. **한글 깨짐 (윈도우)** — 윈도우 명령창은 기본이 한글 코드(CP949)라서, UTF-8 한글을 출력하면 깨집니다.
   → 출력을 UTF-8로 강제하고, 안 되면 자동으로 다른 인코딩으로 시도하게 했습니다. 한글을 명령어 인자로 직접 넘기지 않고 파일을 거치게 했습니다.
2. **서버가 안 꺼지고 쌓임** — 테스트하며 서버를 여러 번 켜다 보니 같은 포트에 유령 프로세스가 쌓였습니다.
   → 다시 켜기 전에 그 포트를 쓰는 프로그램을 찾아 정리하도록 했습니다.
3. **Claude 위치를 못 찾음** — 설치 위치가 PC마다 다를 수 있습니다.
   → 여러 경로를 순서대로 뒤지게 했습니다.
4. **공유했더니 남의 화면에서 안 됨** — 주소가 "내 PC"로 고정돼 있어서, 받은 사람 브라우저는 자기 PC를 찾고 있었습니다.
   → 주소를 "지금 접속한 서버"로 자동으로 맞추게 고쳤습니다.
5. **검색이 0건** — "월간"으로 찾는데 글 제목은 "월말"이라 안 잡혔습니다.
   → 비슷한 말 목록을 만들어 넓게 찾게 했습니다.

## 지킬 규칙 (글을 고칠 때마다)

- 글을 추가/삭제하면 **세 곳을 같이 고친다**: ① 사이드바 메뉴 ② 카테고리 개수 ③ 목차 파일.
- 새 정보는 넣기 전에 **중복·충돌 검사 도구**를 돌린다.
- 비밀번호·IP·계정 같은 **민감정보는 절대 저장하지 않는다.**
- 도구를 고치면 **직접 실행해서 확인한다** (최소 3가지 경우로).
- T-Code는 항상 **"코드 — 화면명"** 형식으로 적는다.
