# 08 — 자율 스킬 루프와 위임 플레이북 · Autonomous Skill Loop & Delegation Playbook

> **"일마다 에이전트를 새로 만들면 2주 안에 죽는다. 대신 일 하나당 3단 레이어 매뉴얼(Skill)을 만들어라."**  
> Anthropic과 Vercel의 실전 엔지니어링 교훈에 기반하여, 거대한 전역 규칙의 인지 부하를 줄이고 개별 일감을 완벽하게 위임·자가관리하는 실천 지침입니다.

---

## 1. 왜 에이전트 체이닝 대신 '매뉴얼(Skill) 캡슐화'인가?

많은 AI 자동화 시도가 실패하는 이유는 **"일마다 별도의 전문 에이전트를 만들고 이들을 파이프라인으로 연결"**하기 때문입니다. 업무 요구사항이나 시스템 화면이 조금만 바뀌어도 에이전트 간 배선이 끊어지고, 사용자는 온종일 배선 디버깅에 매달리게 됩니다.

가장 강력하고 지속 가능한 방식은 **단일 프론티어 범용 AI 모델(Claude Code, Antigravity, Gemini 등)에게 잘 구조화된 '일 단위 매뉴얼(Skill)' 폴더를 제공하는 것**입니다.

---

## 2. 스킬의 3단 레이어 (Process · Toolbox · Proof)

스킬은 하나의 업무를 독립적으로 완수하기 위한 디렉토리 단위입니다.

```
skills/<job-id>/
├─ SKILL.md              # 1층: 프로세스 (트리거, 실행 순서, 판단 규칙, 증명 체크리스트)
├─ files/                # 2층: 툴박스 (스크립트, 자리표시자 템플릿, 참조값)
│   ├─ INDEX.md          # 툴박스 도구 한 줄 색인
│   ├─ *.py / *.sh       # 기계적 추출/계산 스크립트
│   └─ *-template.md     # [자리표시자]가 든 뼈대 서식
├─ examples/             # 2층: 툴박스 (통과되었던 고품질 완성본 예시)
└─ notes.md              # 자가 수정 이력: 오류 -> 레이어 진단 -> 영구 수정
```

### 레이어 1: 프로세스 (Process — `SKILL.md`)
- 어떤 말이 나오면 시작하는지(Trigger), 어떤 순서로 판단하는지 적습니다.
- 조건문("만약 X라면 Y한다")과 과거의 함정/예외 처리가 포함됩니다.

### 레이어 2: 툴박스 (Toolbox — `files/` & `examples/`)
- AI가 매번 스크립트를 새로 짜거나 서식을 지어내지 않도록, 반복되는 파이이썬 스크립트와 `[대괄호]` 서식을 폴더에 얼려둡니다.
- 만족스러웠던 과거 완성본(`examples/`)은 어떤 장황한 설명보다 AI에게 정확한 톤과 규격을 가르칩니다.

### 레이어 3: 증명 (Proof — 실패할 수 있는 객관적 검증)
- AI가 자기 글을 읽고 "괜찮아 보인다"고 하는 것은 검증이 아닙니다.
- **실패할 수 있는 외부의 사실** 5~10개를 체크리스트로 고정합니다:
  - 원본 데이터 파일과 숫자가 100% 일치하는가?
  - 미해결된 자리표시자(`[미정]`)가 0건인가?
  - 테스트 스크립트 종료 코드가 0인가?
  - 표기 규칙(`코드 — 명칭`)을 100% 준수했는가?

## 3. AI의 자율 운영 루프: 스스로 생성하고, 스스로 고친다

### 1) 자동 탐색 및 실행 (Auto-Invoke)
사용자가 업무를 지시하면, AI는 `skills/INDEX.md`를 먼저 스캔합니다. 해당 스킬이 존재하면 스킬의 절차를 따르고, **출력 전 증명(Proof) 체크리스트를 통과했는지 스스로 확인한 뒤** 최종 결과물만 사용자에게 제출합니다.

### 2) 스킬 자가 추출 (Self-Extraction)
사용자가 같은 작업을 2회 이상 반복 지시하거나, 만족스러운 일회성 산출물이 통과되었을 때:
AI는 즉시 템플릿(`skills/_template/`)을 바탕으로 새로운 스킬을 폴더로 패키징하고 `skills/INDEX.md`에 등재합니다. 다음 번 실행부터는 설명할 필요 없이 바로 최고 품질의 결과가 나옵니다.

### 3) 자가 치유 루프 (Self-Healing Loop)
AI가 틀렸을 때 채팅창에서 사과하고 끝내면 다음 세션에 같은 실수를 반복합니다.
AI는 실수가 발생했을 때 3단 레이어로 원인을 진단합니다:
- **프로세스 문제**: 단계 누락, 규칙 부재 -> `SKILL.md` 보강
- **툴박스 문제**: 낡은 템플릿, 스크립트 버그 -> `files/` 수정
- **증명 문제**: 검증 항목이 없어서 실수가 통과됨 -> `SKILL.md`의 증명 체크리스트 추가
그리고 `notes.md`에 진단과 수정 내역을 한 줄 남깁니다. 이렇게 시스템은 쓸수록 복리로 똑똑해집니다.
