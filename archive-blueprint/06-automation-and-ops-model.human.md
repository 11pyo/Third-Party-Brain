# 자동화 · 운영 안전 모델 (사람용)

아카이브/대시보드 바깥의 반복 작업을 자동화하고, **"읽을 수만 있고 쓸 수는 없는" 시스템**을 안전하게 다루는 패턴들입니다.

## 1. 스스로 갱신되는 잠긴 산출물 (생성기 패턴)

정형 보고용 스프레드시트를 *손으로 고치지 않고* **생성기 스크립트로만** 만드는 패턴:

- 표의 누계·총계·차트가 **수식·참조로 자동 갱신** — 값 한 칸만 바꾸면 나머지 따라옴.
- **연/월 자동 확장** — 행 하나 추가하면 표·차트 범위가 자동으로 그 영역까지 포함(차트 앵커를 데이터 크기로 동적 계산).
- **시트+구조 보호로 잠금** — 사람이 임의로 못 고치게. 갱신은 생성기만.
- **무손실 시트 재정렬** — 셀·서식·차트는 건드리지 않고 *파일(zip) 내부의 시트 순서만* 교체(라이브러리 재저장이 서식을 깨는 것을 회피).
- 핵심 규율: **"손으로 고치지 말고 생성기 재실행"** + 파일이 열려 있으면 저장 불가(닫고 재생성).

## 2. ⭐ "구조 시스템으로 읽고, 운영 시스템은 사람 GUI로 가이드" (읽기–가이드 분리)

민감 운영 시스템을 AI가 **직접 쓸 수 없을 때**의 안전 모델:

- 회사가 운영 시스템의 API/접근을 막아둠 → AI는 운영계를 **조회조차 못 함.**
- 대신: **인접한 개발/구조 시스템(읽기 가능)** 으로 구조·소스·데이터 흐름을 읽어 로직을 파악 → 그걸 근거로 **사람이 운영 GUI에서 무엇을 할지 화면·필드·키값·단계로 가이드** → 결과 화면을 받아 다시 해석하고 다음 단계 안내.
- AI = **"보는 눈(구조)＋길잡이(운영 GUI 단계)"**, 실제 실행은 사람. 변경은 정식 절차로.
- 일반화: **권한이 막힌 환경에서도, 읽을 수 있는 인접 시스템 ＋ 사람 실행**의 조합으로 가치를 낸다.

## 3. 업적 자동 적재 (크로스-레포 append-only)

프로젝트에서 의미 있는 성과가 나오면 별도 "커리어 아카이브"에 자동 적재:

- append-only · 중복 방지(ID/제목 dedup) · **공개수준 분류**(공개 / 사내 / 기밀) — 기밀은 외부 자료에 미포함.
- 프로젝트 지침에 "유의미 성과 → 적재" 규율을 박아 자동화.

## 보안 / 공개수준 계층 (정직 원칙)

- **공유본**(예: LAN 공유)엔 고객명·실금액·문서번호·사번 익명화/미기록.
- **내부 트래커**는 실명·실번호 OK(접근 제한된 개인/팀용).
- **기밀/PII**(전화·비밀번호 등)는 **비공유 로컬에.**
- ⚠️ **가역 인코딩(base64)·시트 보호는 "암호화가 아님"** — 억지력일 뿐입니다. 정직하게 한계를 명시하세요(진짜 보호는 *"공유되지 않는 위치"*).
