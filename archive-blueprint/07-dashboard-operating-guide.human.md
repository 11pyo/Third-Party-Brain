# 대시보드 운영 가이드 — 규칙 & 사용법 (사람용)

> `05-operational-layer`가 **"왜 이런 레이어가 필요한가(개념)"**라면, 이 문서는 **"그래서 실제로 어떻게 굴리나(운영 매뉴얼)"**입니다.
> 지식 아카이브(`archive.html`)가 *정리된 지식*을 담는다면, 대시보드는 *지금 진행 중인 일·문의·사람*을 담습니다. 둘은 한 폴더에서 같이 돕니다.
> ▶ **실행 가능한 익명 동작본**: `reference-implementation/dashboard/` — 이 문서가 설명하는 보드가 그대로 도는 샘플(더블클릭 실행, 데이터는 전부 가상).

원본 사례는 1인이 모듈(예: SAP SD) 운영을 맡으면서, 여러 AI 대화 세션이 같은 작업판을 동시에 갱신해도 어긋나지 않게 만든 대시보드입니다. 서버·DB 없이 **파일 몇 개 + 더블클릭**으로 돕니다.

---

## 1. 구성 파일 4개

| 파일 | 역할 | 누가 쓰나 |
|------|------|----------|
| `tasks.md` | **정본(正本).** 프로젝트 태스크(개발·운영)의 칸반·상세를 마크다운으로. 사람이 읽고 고치는 원본. | 사람·AI 직접 편집 |
| `task-board.html` | **화면.** `tasks.md`를 미러링한 단일 HTML 보드. 더블클릭으로 브라우저에서 열림(서버 불요). | 정본을 보고 미러 갱신 |
| `inquiry-log.js` | **문의 처리이력 데이터.** 추가전용(append-only) 푸시로그. `task-board.html`이 `<script src>`로 읽음. | ⚠️ **직접 편집 금지 — 헬퍼로만** |
| `log-inquiry.py` | **문의 로그 헬퍼.** 한 줄씩 안전하게 덧붙이는 작은 CLI. | 문의 기록/전이/완료 시 호출 |

> 핵심 분리: **프로젝트 태스크**는 사람이 정본 마크다운(`tasks.md`)으로 관리하고 화면에 미러링, **문의 이력**은 헬퍼가 추가전용 로그(`inquiry-log.js`)에 쌓습니다. 둘의 동기화 방식이 다른 이유는 4·5장에서 설명합니다.

---

## 2. 세 개의 보드

화면(`task-board.html`)에는 보드가 3종 있습니다.

1. **프로젝트 태스크 보드** — 일회성 작업(개발/운영 건). 상태 4열 **접수 → 진행중 → 대기 → 완료**.
2. **정기업무 보드** — 주례/월례/연례처럼 *트리거가 오면 반복*되는 일. 일회성과 섞이지 않게 **별도 보드**로 둠(평소엔 "지금 할 일 아님" 상태로 대기).
3. **문의 처리이력 보드** — 일반·단순·긴급 문의. 역시 **접수 → 진행중 → 대기 → 완료** 4열. 데이터는 `inquiry-log.js`.

### 카드는 무엇으로 구성되나
- **ID** (예: `DEV-001`, `OPS-002`, 문의는 `INQ-260601-101500`) + **제목**
- **요청자·조직 칩** — 코드 옆에 작게: "누가·어느 조직이 요청했나"를 한눈에
- **기한 / 다음 액션** — 당장 뭘 해야 하는지
- **상세**(접기/펼치기) — 처리 이력·근거·참조 앵커
- **완료 열**은 높이를 고정하고 **스크롤**, 카드는 **최신순**(가장 최근 완료가 위)

**완료 열** 머리에는 **`+전체보기`** 버튼이 있어(완료 카드가 1건 이상일 때), 누르면 완료 카드를 큰 모달로 모아 봅니다(완료가 쌓였을 때 한눈에 보기 좋게).

## 3. 문의 로그의 핵심 — 추가전용 + id 병합 (여러 세션이 동시에 써도 안전)

이게 이 대시보드에서 가장 중요한 패턴입니다. 여러 AI 세션(또는 사람+AI)이 같은 로그를 동시에 갱신해도 충돌이 안 나게:

- **추가만 한다 (append-only)** — `inquiry-log.js`는 한 줄 = 한 이벤트. 기존 줄을 고치지 않고 **새 줄을 덧붙임**.
  ```js
  window.INQUIRY_LOG.push({id:"INQ-...", date:"...", type:"단순문의", q:"문의 요약", by:"기록자", status:"접수"});
  window.INQUIRY_LOG.push({id:"INQ-...", status:"진행중"});          // 같은 id — 상태만 덧붙임
  window.INQUIRY_LOG.push({id:"INQ-...", status:"완료", a:"처리 요약"}); // 같은 id — 답변 채우며 완료
  ```
- **id로 병합한다 (id-merge)** — 화면이 그릴 때 **id별로 줄을 접어(fold) 마지막 값으로 병합**. 그래서 "접수→진행중→완료"라는 *상태 전이*가 파일에선 "기존 줄 수정"이 아니라 **"새 줄 덧붙임"**으로 표현됩니다. (빈 값은 병합에서 무시 → 준 필드만 덮어씀)
- **헬퍼로만 쓴다** — 로그 파일을 직접 손대지 않고 작은 스크립트(`log-inquiry.py`)가 줄을 덧붙입니다. 두 세션이 동시에 덧붙여도 줄이 섞이지 않게, 헬퍼는 **짧은 OS 파일락**으로 덧붙임 구간을 보호합니다(락이 실패해도 기록 자체는 유지하는 best-effort).
- **`file://` 우회** — 브라우저가 로컬 파일을 `fetch` 못 하는 제약을, 데이터를 `<script src="inquiry-log.js">`로 불러오는 방식으로 우회. HTTP 서버가 필요 없습니다.

> 왜 중요한가: **잠금장치나 데이터베이스 없이도, 여러 자율 AI가 같은 작업판을 드리프트(상태 어긋남) 없이 동시 갱신**할 수 있게 됩니다. 일반적인 파일 덮어쓰기 방식이면 한 세션의 기록이 다른 세션 것을 날렸을 겁니다.

## 4. 운영 규칙

대시보드를 만지는 모든 사람·AI가 지키는 규율입니다.

- **R1. 정본은 마크다운, 화면은 미러.** 프로젝트 태스크의 진실은 `tasks.md`. `task-board.html`은 그걸 비추는 화면일 뿐이니, 태스크를 바꾸면 **둘 다** 맞춥니다. (정본↔화면 동기화는 "작업의 일부")
- **R2. 문의 로그는 헬퍼로만.** `inquiry-log.js`를 손으로 편집하지 않습니다. 추가전용 + id 병합이라는 무결성·동시성 보장이 깨지기 때문(세션 제한이 아니라 데이터 안전 때문).
- **R3. 모든 세션이 전권, 충돌은 2규칙으로 막는다.** 이 폴더를 보는 **어느 대화 세션이든 모든 파일을 고칠 권한**이 있습니다(파일 도메인 분리 없음 — 빈 세션 1개가 프로젝트 1개를 끝까지 맡는 모델). 대신 ① **편집 직전 항상 파일을 다시 읽고**(다른 세션이 바꿨을 수 있음) ② **문의 로그만은 헬퍼로** 갱신합니다.
- **R4. 요청자·조직 칩을 채운다.** 문의·태스크엔 "누가·어느 조직이 요청했나"를 칩으로 남겨, 나중에 추적·라우팅이 됩니다.
- **R5. 추가·삭제 시 3곳 동기화.** 태스크를 추가/삭제하면 ① 정본 `tasks.md` ② 화면 `task-board.html` ③ (집계 카운트가 있으면) 합계 숫자를 함께 맞춥니다.
- **R6. 정기업무는 분리해서 트리거 대기.** 월례·연례 업무는 일회성과 섞지 말고 정기 보드에 두되, 평소 상태는 "트리거 대기"로. 트리거(메일·요청 수신)가 오면 그때 착수.
- **R7. 완료는 스크롤·최신순·전체보기.** 완료가 계속 쌓이므로 완료 열은 높이 고정+스크롤, 최신이 위, 한눈에 볼 땐 전체보기 모달.
- **R8. 민감정보는 데이터 파일(로컬)에만, 공개본엔 패턴만.** 실제 `tasks.md`·`inquiry-log.js`엔 고객명·문서번호·금액·담당자명이 들어갑니다 — 이건 **로컬/사내용**입니다. 공개(이 블루프린트 같은)에는 **구조·규칙·익명 예시만**. 전화·이메일·사번 같은 PII는 데이터 파일에도 넣지 않고 비공유 로컬에 따로 둡니다.

## 5. 사용법 (How-to)

### A. 문의 한 건을 처리한다 (접수 → 전이 → 완료)

```bash
# ① 접수 — 문의가 들어오면 즉시 (보드 '접수' 열 맨 위에 뜸)
python log-inquiry.py --new --type 단순문의 --q "<문의 요약>" --by <기록자> --req "<요청자·조직>"
#   → stdout 'NEW id=INQ-YYMMDD-HHMMSS' 의 id 를 기억해 둔다 (이후 전이·완료에 씀)

# ② 상태 전이 — 작업 시작/보류 (같은 id)
python log-inquiry.py --id <그-id> --status 진행중      # 또는 대기

# ③ 완료 — 답변이 끝나면 (같은 id에 처리 요약·참조 채우고 완료로)
python log-inquiry.py --done --id <그-id> --a "<처리·답변 요약>" --ref "#<관련-아티클-앵커>"
```

- 접수와 동시에 답이 끝났으면 ①에서 `--a`(또는 `--status 완료`)까지 주면 바로 완료로 들어갑니다.
- 유형: `단순문의 | 일반요청 | 긴급문의` · 상태: `접수 | 진행중 | 대기 | 완료`
- 필드: `{id, date, type, q(질의), a(답변), by(기록자), req(요청자·조직), ref(아카이브 앵커), status}`

### B. 프로젝트 태스크를 추가/갱신한다

1. **정본** `tasks.md`에 해당 카드의 상세 섹션(본문 + 🤖 AI 참조 로그)을 추가/수정.
2. **화면** `task-board.html`의 태스크 배열(`const TASKS = [...]`)에 같은 카드를 미러링 — 상태·요청자·기한·다음 액션 같은 카드 메타는 **이 배열을 1순위 출처**로 삼는다.
3. 추가·삭제면 **집계 숫자**도 맞춤(R5).

> **2026-08-25 갱신 — 위 1단계 서술 정정**: 예전엔 여기서 `tasks.md` 상단의 손관리 칸반 요약 표(ID·분류·제목·상태·요청자·기한·다음 액션을 모은 표)에 먼저 행을 적으라고 안내했다. 실제 운영해 보니 이 표가 카드 본문·보드 배열과 함께 **3중 수기입력**이 되면서 가장 먼저 낡는 층으로 확인됐다(카드 본문·보드 배열은 최신 상태로 갱신됐는데 요약 표만 옛 상태로 남아있던 사례). 그래서 이 표는 걷어내는 중이고, 카드 메타의 단일 출처를 화면(`task-board.html`)의 `const TASKS` 배열로 정리했다(위 2단계). 정본(`tasks.md`)이 커져 세션이 한 번에 통째로 읽기 어려워지는 문제에는 **경량 인덱스 생성기**(살아있는 카드 목록 + 카드별 라인범위만 추출)를, 3중 수기입력의 드리프트에는 **자동 대조 점검기**(세 벌을 교차 대조해 불일치만 보고하고 직접 고치지는 않음 — 무엇이 맞는지는 사람이 판단)를 함께 두는 방식이 실사용에서 검증됐다. 상세는 `CHANGELOG.human.md` 2026-08-25 항목 참조.

### C. 화면에서 카드를 손본다 (브라우저 임시 편집)

- 카드의 ✏️ 편집은 **이 브라우저(localStorage)에만** 저장됩니다(정본은 자동으로 안 바뀜). 빠른 메모·정리용.
- 정본에 반영하려면 편집바의 **「변경분 내보내기(JSON)」**로 바뀐 카드만 뽑아, 그 내용을 `tasks.md`(+ `task-board.html`)에 옮깁니다. (localStorage override를 정본에 흘려보내는 한 방향 동기화)

### D. 새로고침 = 반영

화면은 정적 파일이라, 정본/로그를 고친 뒤 **브라우저 새로고침**하면 반영됩니다(빌드·배포 없음).

## 6. 왜 데이터 파일은 공개하지 않나 (익명화 원칙)

실제 `tasks.md`·`inquiry-log.js`에는 **고객사명·실명·문서번호(주문/계산서)·금액·내부 코드·결재번호**가 그대로 담깁니다 — 이건 일을 하기 위한 로컬/사내 데이터입니다. 그래서:

- **공개하는 것**: 보드 구조, 추가전용 id-병합 로그 패턴, 헬퍼 CLI 설계, 운영 규칙 — 즉 *재현에 필요한 방법론*과 *익명 예시*뿐.
- **공개하지 않는 것**: 실제 데이터 파일 자체, 고객/사람 이름, 문서·금액·결재 번호, 사내 커스텀 코드 세부, 그리고 전화·이메일·사번 같은 PII.
- 공유(LAN·공개)본에 무언가를 올릴 땐 항상 이 경계를 먼저 확인합니다.

## 설계 원칙 (요약)

1. **정적 우선** — 대시보드도 서버 없이 더블클릭. 공유는 파일 복사나 아카이브 검색서버 공유에 얹기.
2. **동시성은 추가전용으로** — 락·DB 대신 "덧붙이고 id로 병합". 손실·충돌 0.
3. **정본↔화면 분리, 동기화는 규율로** — 진실은 마크다운, 화면은 미러.
4. **살아있는 문서는 AI가 유지** — 사람이 매번 갱신하는 게 아니라, 업무 흐름에 규율로 묶어 어느 세션이 와도 같게.
5. **공개 경계는 항상 명시** — 데이터는 로컬, 패턴만 공개.
